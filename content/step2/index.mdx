# 2단계 선배 PR 카드

2단계에서 UI를 붙이면서 생기는 고민들을 선배 PR에서 찾아봅니다.

---

## 그룹 선택

코드랩에서 세운 **액션 플랜 방향**에 맞는 그룹을 선택하세요.

### A그룹 — 도메인을 지킨다

"선배는 도메인 수정 없이 어떻게 UI를 붙였나? 내 코드에 적용할 포인트는?"

| 번호 | 주제 | 선배 크루의 상황 |
|------|------|-------------|
| [A-1. Model/View 분리](/step2/a1-model-view) | DOM 접근 코드 위치 | "Model 클래스 안에 DOM 접근 코드가 생겼어요" |
| [A-2. 의존 방향](/step2/a2-dependency) | 단방향 의존 | "View에서 Controller를 import해서 데이터를 가져왔어요" |
| [A-3. 도메인 로직 위치](/step2/a3-domain-logic) | utils? reducer? | "도메인 로직이 utils나 상태 관리 코드에 섞여있어요" |

### B그룹 — 테스트를 확장한다

"선배는 UI 테스트를 어떻게 작성했나? 도메인 테스트와 어떻게 분리했나?"

| 번호 | 주제 | 선배 크루의 상황 |
|------|------|-------------|
| [B-1. UI 테스트 작성](/step2/b1-ui-test) | testable한 코드 | "DOM이 없어서 테스트가 통과하지 않아요" |
| [B-2. 테스트 분리](/step2/b2-test-separation) | 파일 분리 기준 | "기능 테스트와 UI 테스트가 한 파일에 섞여있어요" |
| [B-3. 테스트 전략](/step2/b3-test-strategy) | 범위와 균형 | "성공 케이스만 있거나 에러 케이스만 있어요" |

---

> 각 카드 하단의 **탐색 미션 열기** 는 코치 안내 후 열어보세요.
