# anti-02. MasterCard 2-series 누락

**빈도: 25건 중 11+건** — 이 패턴은 단순 코드 실수가 아니라, *요구사항을 그대로 옮긴 결과*다.

## 패턴 한 줄

8기 페어 거의 전원이 README에 *"MasterCard: `51`~`55`로 시작하는 16자리"* 라고 적고, 코드도 그렇게 작성했다. 실제 MasterCard에는 **2221~2720(2-series)** 도 포함된다는 사실은 누구도 검증하지 않았다.

## AS-IS 코드 (8기 PR 발췌)

> 🔍 **읽기 전에**
>
> "내 PR의 README와 카드 브랜드 판별 함수를 열어보자. `51`만 있는가? `2221`도 있는가?"

### 사례 A — README와 코드가 같이 누락

[PR #520](https://github.com/woowacourse/react-payments/pull/520) — `README.md`

```md
| 브랜드     | 식별 규칙                        |
| ---------- | -------------------------------- |
| Visa       | `4`로 시작하는 16자리 숫자       |
| MasterCard | `51`~`55`로 시작하는 16자리 숫자 |
```

[PR #524](https://github.com/woowacourse/react-payments/pull/524)도 같은 표를 그대로 복사한 README. 같은 PR의 판별 함수도 `51~55`만 다룬다.

### 사례 B — prefix 기반 판별 함수

[PR #518](https://github.com/woowacourse/react-payments/pull/518) — `CardPreviewContainer.tsx`

```tsx
// src/feature/CardRegister/components/CardPreviewSection/CardPreviewContainer/CardPreviewContainer.tsx
const getBrandName = (cardNumbers: string[]): 'visa' | 'masterCard' | null => {
  const fullNumber = cardNumbers.map((chunk) => chunk.padEnd(4, '#')).join('');
  if (fullNumber.startsWith('4')) return 'visa';

  const prefix = Number(fullNumber.slice(0, 2));
  if (prefix >= 51 && prefix <= 55) return 'masterCard';

  return null;
};
```

여기서 또 한 가지 — 16자리가 *완성되기 전에도* `startsWith('4')` 만으로 visa 판정이 떨어진다. *"4"* 한 글자만 입력해도 visa 로고가 노출되는 식이다.

## 16자리 완성 전 판별 — 함께 따라오는 신호

## 토론 질문

1. README에 *"51~55"* 라고 적기 전에 — 실제 MasterCard 카드의 BIN 범위는 어떻게 확인할 수 있을까? *공식 자료* 한 가지를 찾아보자.
2. 카드 번호가 *3자리*만 입력됐을 때 브랜드 로고를 보여주는 것은 옳은 UX인가? *완성된 16자리*에서만 판별해야 한다면 — 지금 코드의 어디를 바꿔야 하는가?
3. 같은 페어 25팀이 같은 누락을 했다 — 이건 *코드의 문제*인가, *명세 검증의 문제*인가, 아니면 *둘 다*인가?

## 단서 (정답 아님)

- 실제 MasterCard 공식 BIN 범위: `51-55` *and* `2221-2720`. 위키피디아 [Payment card number](https://en.wikipedia.org/wiki/Payment_card_number) 또는 MasterCard 공식 문서에서 확인 가능.
- 16자리 완성 전 판별 회피: `cardNumber.length < 16 ? null : detectBrand(cardNumber)` 형태로 *완성 시점*만 판별. 또는 *prefix만으로도 확정 가능한 자릿수*까지 점진적으로 보여주려면 명세를 정교화해야 한다.
- *판별 함수는 순수 함수*로 격리. 자동화된 테스트로 *알려진 카드번호*에 대한 출력을 검증할 수 있다 — 미션 명세에는 안 적혀 있어도 도메인 검증의 자연스러운 출발점.
- 미션 명세를 *그대로* 옮기는 대신 *도메인을 한번 의심*하기. 결제 시스템 도메인은 명세보다 항상 더 풍부하다.
