# Q7. 카드 정보 input — 제약은 어떤 도구로 거는 게 맞을까?

## 크루의 질문

> "카드 정보를 입력하는 input 컴포넌트에서 최대 길이가 넘으면 입력을 못하게 하기 위해서 maxLength라는 props를 받도록 했는데, input 태그에서 maxLength를 설정하려면 type='number' 상태가 불가능해서 문자열이 입력이 가능한 상태가 되었고, input 기본 속성으로 *최대 길이 제한* vs *문자열 입력 제한* 중 선택해야 했어서 결국 maxLength를 선택하고 카드 정보를 입력하는 input 컴포넌트에서는 *고정으로 문자열을 입력하지 못하도록* 함 (코드 작성이 더 쉬워서). 근데 input이 문자열을 입력하지 못하게 된다면 *범용성이 떨어지게 될 것 같아서* 좋지 않은 선택이라는 생각이 들기도 했는데, 한편으로는 *카드 정보 입력이라는 도메인 규칙*에서는 나쁘지 않은 선택이었다는 합리화를 하기도 했습니다." — 라바·찰리 페어

## AS-IS 코드

```jsx
// 두 패턴이 공존하는 자리 — 어느 쪽이 더 견딜까?

// (a) type="number" + 자동 길이 제한 X
<input
  type="number"
  value={cardNumber}
  onChange={handleChange}
  // type=number는 maxLength가 무시된다
/>

// (b) type="text" + maxLength + 별도 숫자 검증
<input
  type="text"
  inputMode="numeric"  // 모바일 숫자 키패드 유도
  pattern="[0-9]*"
  maxLength={4}
  value={cardNumber}
  onChange={(e) => {
    if (/^\d*$/.test(e.target.value)) handleChange(e);
  }}
/>
```

라바·찰리 페어가 발견한 *trade-off의 본체*: HTML input은 `type="number"`와 `maxLength`를 *동시에 안전하게 적용해주지 않는다*. 그래서 *최대 길이 제한*이냐 *문자열 입력 제한*이냐 중 하나를 골라야 한다.

## 공식문서 단서 — *MDN HTMLInputElement*

이 카드는 React 영역이 아니라 *HTML 표준* 영역입니다. 두 권위 문서를 함께 봅니다.

### MDN — `<input type="number">`
- 원문: [developer.mozilla.org/en-US/docs/Web/HTML/Element/input/number](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/number)
- 핵심: `<input type="number">`는 `min`·`max`·`step`을 지원하지만 **`maxLength`는 적용되지 않는다.** 길이 제한이 필요하면 다른 도구를 써야 한다.

### MDN — `inputmode` 속성
- 원문: [developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/inputmode](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/inputmode)
- 핵심: `inputmode="numeric"`을 `type="text"`와 함께 쓰면 **모바일에서 숫자 키패드를 띄우면서도 maxLength·pattern을 함께 쓸 수 있다.** 카드번호 입력의 *현실적 표준*에 가깝다.

### React docs — `<input>` 컴포넌트
- 원문: [react.dev/reference/react-dom/components/input](https://react.dev/reference/react-dom/components/input)
- 핵심: React가 별도로 만든 행동이 아니라 *HTML 표준 그대로* 동작한다. `type="number"`의 한계는 React에서도 같다.

## 추가 읽을거리 — Kent C. Dodds · Dan Abramov

### Kent C. Dodds — Stop using isLoading booleans (간접 연결)
- 원문: [kentcdodds.com/blog/stop-using-isloading-booleans](https://kentcdodds.com/blog/stop-using-isloading-booleans)
- 한 줄 요약: *불가능한 상태*를 만들지 않으려면 *입력의 종류 자체를 좁혀라*. `type="number"`로 유효 값의 범위를 *플랫폼이 강제*하는 결정과 같은 결.

### Dan Abramov — Writing Resilient Components
- 원문: [overreacted.io/writing-resilient-components](https://overreacted.io/writing-resilient-components/)
- 한 줄 요약: 공통 Input 컴포넌트의 *범용성*과 *도메인 안전성* 사이의 trade-off. 라바·찰리가 인지한 *"범용성이 떨어진다"*는 우려의 깊이를 다룬다.
