## 페어 고민 (PR body 핵심 발췌)

- 이번 1단계에서는 카드 번호, 유효기간, CVC처럼 각각 다른 입력값을 다루다 보니 검증 로직과 에러 상태를 어떤 단위로 관리해야 하는지를 많이 고민했습니다.
- 처음에는 하나의 errorMode 상태를 여러 입력 컴포넌트가 공용으로 사용했는데, 이 방식은 특정 필드에서 발생한 에러가 다른 필드에도 같이 표시되는 문제가 있었습니다.
- 해당 문제를 해결하기 위해 리팩토링 과정에서 커스텀 훅을 사용하여 입력값과 에러 모드를 객체로 묶어 넘겨주었습니다.
- 결국 확장성과 응집도를 고려해 페이지 컴포넌트에서 카드 번호, 유효기간, CVC 상태를 함께 관리하도록 했습니다.
- 커스텀 훅을 사용하는 현재 방식과 `useReducer`훅을 사용해 상태를 컴포넌트에서 분리하여 관리하는 방식의 차이점과 현재 코드에 적절한 방식은 무엇인지 우코의 의견을 듣고 싶습니다!
