## 페어 고민 (PR body 핵심 발췌)

- 이번 페어에서는 먼저 요구사항 정리 -> 설계문서 작성 -> UI 구현 -> 비즈니스로직 작성 순으로 진행했습니다.
- `AddCardPage`에서 카드 정보를 `{ cardNumbers, expirationPeriod, cvc, cardBrand }` 형태로 묶어 `CardInfoFormValue` 타입으로 관리했습니다.
- 에러 처리와 validation은 각 Field 컴포넌트 레벨에서 담당하고, 그 결과만 `isValid` 같은 필드로 상위에 전달하는 방향으로 결론을 내렸습니다.
- 현재 `CardNumbersField`, `ExpirationPeriodField`에서 에러 상태를 단일 `errorStatus`로 관리하다 보니, 여러 input 중 하나에서 발생한 에러가 다른 input 조작 시 덮어써지는 버그가 존재합니다.
- `formValue`에 저장하지 않고 렌더링 시점마다 `categorizeCardBrand(cardNumbers)`로 계산하는 방식도 고려했습니다.

interface CardInfo {

interface FieldState<T> {
