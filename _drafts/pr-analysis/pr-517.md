## 페어 고민 (PR body 핵심 발췌)

- 일단 오버엔지니어링을 절대로 하지 말자는 생각으로 미션을 수행했습니다.
- 좋은 코드를 작성하는 것도 좋지만, 그리고 완벽한 설계를 하는 것도 좋지만, 일단 요구사항을 만족하는 돌아가는 코드를 만드는것이 무엇보다 중요하다고 생각하였습니다.
- 실제로 Input 컴포넌트를 도메인과 무관한 원자 컴포넌트로 만들고 나니, CardNumberInputField, CardValidityPeriodInputField, CardCVCInputField 전부에서 별도 수정 없이 그대로 재사용할 수 있었습니다.
- 카드 입력값(cardNumber, validityPeriod, CVC) 은 `Card` 프리뷰와 공유해야 하므로 페이지(`AddNewCardPage`)로 끌어올렸습니다.
- 반면 에러 상태(`inputStatus`) 는 카드 프리뷰가 알 필요가 없으므로, 각 `CardXxxInputField` 내부에 로컬로 두었습니다.
